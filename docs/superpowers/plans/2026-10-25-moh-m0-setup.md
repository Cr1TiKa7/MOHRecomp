# M0 Einrichtung – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Toolchain auf D: einrichten und das Projekt `MOHRecomp` aus der PAL-Disc anlegen. Eine Release- und eine Entwicklungs-`.exe` bauen. Ein automatischer Smoke-Test beweist über den Debug-Port, dass das Spiel bis zum ersten Bild startet.

**Architecture:**
- Das portable Toolchain-Paket `cmake-clang-v1` liegt mit Temp und Toolchain-Cache unter `D:\RecompDev`.
- Ein Umgebungsskript setzt alle Variablen pro PowerShell-Sitzung.
- `setup_project.ps1` aus PSXRecomp legt das Repo an, probt die Disc und erzeugt den Spiel- und OpenBIOS-C-Code. Gebaut wird mit `psxrecomp_cli.py rebuild`.
- Ein Python-Smoke-Test (nur Standardbibliothek) startet die Entwicklungs-`.exe` versteckt, spricht den TCP-Debug-Port an und prüft Bildwechsel und Bildinhalt.

**Tech Stack:** PowerShell 5.1/7, Python 3.13 (`py -3`), Git for Windows (inkl. Git-Bash), PSXRecomp (Submodul, `master`), Toolchain `cmake-clang-v1` v1.0.14 (Clang, CMake, Ninja), SDL3 (vom Build geholt).

**Spec:** `docs/superpowers/specs/2026-10-25-moh-pc-port-design.md`. Liegt bis Task 2 in `D:\Projekte\Solution1\docs\superpowers\specs\`, danach im Projekt-Repo.

## Global Constraints

- **Speicherort:** Toolchain, Temp, Toolchain-Cache, Klone und Build-Ausgaben liegen nur auf D: unter `D:\RecompDev`. Auf C: entsteht nichts Neues, insbesondere kein `%LOCALAPPDATA%\retcomm`.
- **Disc:** `D:\Downloads\Medal of Honor (Europe)\Medal of Honor (Europe).cue` (PAL UK, SLES-02470). Kein `-StageDisc`: Die Disc wird nie ins Repo kopiert.
- **Nie committen:** Disc-Images (`*.bin`, `*.cue`, `*.iso`), BIOS-Dumps, Logs, `overlay_captures.json`, Savestates, Speicherkarten.
- **BIOS:** nur OpenBIOS, kein `-Bios`.
- **Framework:** `https://github.com/RetroPortingToolKit/psxrecomp.git`, Branch `master` zum Ausführungszeitpunkt. Wird als Submodul gepinnt, der SHA steht in der Commit-Nachricht.
- **Toolchain:** `cmake-clang-v1-windows-x64.zip` aus Release `v1.0.14` von `RetroPortingToolKit/RetroPorting-Toolchains`, Größe exakt `209497009` Bytes.
- **Python:** Windows-natives Python über `py -3`. Kein MSYS2- oder Cygwin-Python.
- **Builds:**
  - `build-release/`: Release, Debug-Server aus
  - `build-dev/`: Release mit `-DPSX_DEBUG_TOOLS=ON`
- **Debug-Port:** `4370`
- **Projektname:** `-Name MOHRecomp -GithubRepo MOHRecomp`, Ordner `D:\RecompDev\MOHRecomp`, Spieler `1`
- **Git:** vorhandene globale Identität. Jede Commit-Nachricht endet mit `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Kein Push, kein GitHub-Remote.

## Review Focus

1. **Disc-Pfad mit Leerzeichen und Klammern** (`Medal of Honor (Europe)`): Setup, Generate und Smoke-Test müssen damit funktionieren. Task 2 und 3 benutzen genau diesen Pfad, nie eine Kopie ohne Leerzeichen.
2. **Downloads oder Caches landen doch auf C:**: Task 3 prüft nach dem Build, dass `%LOCALAPPDATA%\retcomm` nicht existiert.
3. **Debug-Port belegt durch eine hängengebliebene Instanz:** Der Smoke-Test bricht mit klarer Meldung ab, statt sich mit einer alten Instanz zu verbinden. Er beendet seine eigene Instanz in jedem Fall.
4. **Release-Build öffnet versehentlich den Debug-Server:** Task 3 prüft, dass die Release-`.exe` auf 4370 nicht antwortet.
5. **Erzeugter Code ist nicht reproduzierbar:** Ein zweites `generate` auf dieselbe Disc ändert nichts in `generated/` (Task 2).

### Task 3: Entwicklungs-Build und Boot-Smoke-Test

**Files:**
- Create: `tests/smoke/psxdbg.py`: Mini-Client für den Debug-Port

- Create: `tests/smoke/boot_smoke.py`: Startet das Spiel, wartet aufs erste Bild, beendet es
- Create: `tests/smoke/test_helpers.py`: Unit-Tests für die beiden Helfer
- Create: `tools/run-smoke.ps1`: Findet die Dev-`.exe` und startet `boot_smoke.py`
- Create: `docs/DEVELOPMENT.md`: Umgebung, Build-, Regenerier- und Smoke-Befehle

**Interfaces:**
- Consumes:
  - `dev-env.ps1` (Task 1)
  - den Regenerieren-Befehl und das Repo (Task 2)
- Produces:
  - `psxdbg.send(cmd: str, port: int = 4370, timeout: float = 5.0, **params) -> dict`
    - Verbindung pro Aufruf: eine JSON-Zeile `{"id": 1, "cmd": cmd, **params}` senden, eine Zeile lesen, `json.loads` zurückgeben.
    - Wirft `ConnectionError`, wenn niemand lauscht.
  - `psxdbg.port_in_use(port: int = 4370) -> bool`
  - `pngcheck.distinct_colors(path: str, limit: int = 256) -> int`
    - Zählt verschiedene Pixelwerte, stoppt bei `limit`.
    - Unterstützt 8-Bit RGB und RGBA ohne Interlace, alle fünf PNG-Filtertypen.
    - Wirft `ValueError` bei anderen Formaten.
  - `boot_smoke.py --exe PATH --cue PATH [--port 4370] [--timeout 90] [--out DIR]`
    - Exit 0 bei Erfolg, 1 bei Fehlschlag mit einer Zeile Begründung auf stderr.
  - `tools/run-smoke.ps1 [-Build dev|release]`
  - Dev bauen: `py -3 psxrecomp\psxrecomp_cli.py rebuild --config game.toml --project-root . --build-dir build-dev --no-pgo --no-toolchain-download --cmake-extra=-DPSX_DEBUG_TOOLS=ON`

- [ ] **Step 5: Failing Test für den belegten Port, dann `boot_smoke.py` schreiben** (Review Focus 3)

  In `test_helpers.py` ergänzen:

  ```python
  class BootSmokeTests(unittest.TestCase):
      def test_refuses_busy_port(self):
          # Fake-Server auf freiem Port p; subprocess.run([sys.executable, <dir>/boot_smoke.py,
          #   "--exe", "does-not-exist.exe", "--cue", "x.cue", "--port", str(p)], capture_output=True, text=True)
  ```

  Expected: genau dieser Test schlägt fehl (`boot_smoke.py` fehlt). Danach `boot_smoke.py` schreiben, Tests erneut ausführen: 10 Tests, alle OK.

  Ablauf von `boot_smoke.py`:
  1. Ist `port_in_use(port)`: Exit 1 mit `port <p> busy – another runtime running?` (Review Focus 3).
  2. Prozess starten: `[exe, "--game", <repo>/game.toml, "--disc", cue, "--no-launcher", "--hidden-window", "--debug-port", str(port), "--memcard-dir", <out>/memcards]`
     - Arbeitsverzeichnis ist das Verzeichnis der `.exe`.
     - Env zusätzlich `PSX_HOST_MUTE=1`.
     - stdout/stderr nach `<out>/runtime.log`.
     - `<out>` ist standardmäßig `D:\RecompDev\Temp\smoke-<Zeitstempel>`.
  3. `ping` alle 0,5 s bis zur ersten Antwort. Höchstens `timeout` Sekunden, sonst Fehlschlag `debug port never answered`.
  4. **Bildwechsel prüfen:** Zwei `ping`-Antworten im Abstand von 2 s. Das Feld `frame` muss gestiegen sein, sonst `frame counter stuck`.
  5. **Bildinhalt prüfen:** Alle 2 s `screenshot path=<out>/shot-<n>.png`. Erfolg, sobald `distinct_colors(...) >= 16`. Nach `timeout` Fehlschlag `no non-trivial frame`. Die PNGs bleiben in `<out>` liegen.
  6. Im `finally`: `send("quit")` versuchen, 10 s auf Prozessende warten, sonst `kill()`. Die Instanz wird in jedem Fall beendet.

  Das Feld `frame` steht laut Doku in der `ping`-Antwort. Heißt es anders, wird der tatsächliche Name aus der ersten Antwort im Log festgehalten und verwendet.
