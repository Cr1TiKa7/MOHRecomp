# M1 Bis ins Menü – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Automatisch nachweisen, dass Intro-Videos mit Ton laufen und das Hauptmenü per Fernsteuerung bedienbar ist. `SHELL.BIN` wird aus den Disc-Daten vorab nativ kompiliert, damit Menü-Code nicht mehr im Interpreter läuft. Die Speicherkarte wird erkannt.

**Architecture:**
- Ein gemeinsames Python-Modul `psxrun` kapselt Start, Fernsteuerung und Beenden des Spiels. Drei neue Smoke-Tests bauen darauf auf:
  - Intro: Video- und Audio-Nachweis
  - Menü: Menüring per RAM-Index
  - Abdeckung: Interpreter-Anteil ohne Runtime-Autocompile
- Ein AOT-Rezept `aot/overlays.json` beschreibt `SHELL.BIN` als `fixed_address_files` an `0x80039F28`. Der Loader-Code der Boot-EXE dient als Beleg. `psxrecomp_cli generate` erzeugt daraus `generated/overlays_static.c`.

**Tech Stack:** wie M0 (Python 3.13 nur Standardbibliothek, PowerShell, PSXRecomp `7097d53`, Toolchain cmake-clang-v1 1.0.14). Neu: `tools/aot_overlay_pipeline.py` (über `generate`), Debug-Befehle `press`, `read_ram`, `turbo`, `mdec_state`, `audio_wav`, `overlay_loader_status`, `overlay_static_entries`.

**Spec:** `docs/superpowers/specs/2026-10-25-moh-pc-port-design.md`, Meilenstein M1 und Abschnitt 6.1.

## Fakten aus der Erkundung (2026-10-25, Dev-Build, ohne Eingaben)

- **Boot-Ablauf:**
  - Legal-Screen ab Frame ~300
  - EA-Logo-Video ab ~700
  - Historisches Intro-Video ~1500–4800 mit 320×256
  - Hauptmenü ab ~5500
- **Takt:** 50 Bilder pro Sekunde. `turbo enabled=1` beschleunigt nur die Wartezeit.
- **Hauptmenü:** Ring aus 6 Punkten mit RIGHT: `NEW GAME, WAR RECORDS, BRIEFING, MULTIPLAYER, GALLERY, OPTIONS`.
  - `OPTIONS` öffnet mit X ein Untermenü (RIGHT blättert): `PASSWORD, SECRET CODES, CONTROLLER, AUDIO, CREDITS`. Zurück geht mit Dreieck.
  - X auf `NEW GAME` lädt direkt das Spiel (Ladebild „On to Victory!“).
  - Im Menü gibt es **keinen** Speicherkarten-Speichern-Punkt.
- **`SHELL.BIN`:** Rohes Binärformat ohne PS-X-Header. Erstes Wort `7`, bei `LEVEL.BIN` `5`, bei `LEVEL2P.BIN` `6`. Im Menü liegt die Datei unverändert ab **`0x80039F28`**, belegt an 5 Stellen.
  - Die Boot-EXE baut die Adresse bei `0x8003728C: 3C058004` (`lui a1,0x8004`) und `0x80037290: 24A59F28` (`addiu a1,a1,0x9F28`).
  - Die 3 JAL-Ziele der Boot-EXE im Overlay-Bereich sind in keinem Overlay Funktionsanfänge. Sie werden **nicht** als `entries` deklariert.
- **Abdeckung:** Mit Runtime-Autocompile lag der Interpreter-Anteil bei 0,98 % (`234038` von `23866105` Dispatches). Dennoch liefen 418 Mio. Befehle interpretiert (`dirty_ram_stats.insns_run`).
- **Debug-Befehle:**
  - `press buttons=<invertierte Maske> frames=N` (Standard 2)
  - `savestate slot=N op=save|load`
  - `read_ram addr len` liefert `hex`
  - `audio_wav path tap start count` schreibt PCM als 44100 Hz s16 WAV
  - `mdec_state.decode_macroblocks` zählt dekodierte Videoblöcke
- **Speicherkarten:** werden als `card1.mcd`/`card2.mcd` (je 131072 Bytes) im `--memcard-dir` angelegt.

- **Zeitbudgets der Smoke-Tests:** höchstens 180 s pro Test. Bis Frame 5700 wird mit `turbo enabled=1` vorgespult, außer der Test misst Audio.

## Review Focus

1. **Eingaben in Übergängen:** Ein `press` während einer Video- oder Menü-Überblendung wird verschluckt. Der Menütest darf erst zählen, wenn ein RIGHT nachweislich den Index ändert (Task 3).
2. **Stummschaltung verfälscht die Audio-Messung:** `PSX_HOST_MUTE=1` könnte den Abgriff nullen. Eine RMS von exakt 0 wird als „gemuteter Abgriff“ gemeldet, nicht als „kein Ton“ (Task 2).
3. **Alter Runtime-Cache täuscht native Abdeckung vor:** DLLs aus früheren Läufen in `build-dev\cache\SLES-02470` würden ohne Autocompile trotzdem geladen. Der Abdeckungstest löscht diesen Ordner vor dem Lauf (Task 4).
4. **Overlay-Rezept greift beim falschen Overlay:** Wird später `LEVEL.BIN` an dieselbe Basis geladen, darf nativer `SHELL`-Code nicht laufen. Die Byte-Guards der Runtime verhindern das. Der Abdeckungstest prüft nach X auf `NEW GAME` zusätzlich, dass das Spiel weiterläuft und der Bildzähler steigt (Task 4).
5. **Andere Disc oder anderer Dump:** Das Rezept ist an den SHA-256 des Datentracks gebunden. Bei einer anderen Disc muss `generate` mit „not applicable“ abbrechen, statt falschen Code zu bauen. Task 4 prüft das mit einer manipulierten Hash-Angabe.
